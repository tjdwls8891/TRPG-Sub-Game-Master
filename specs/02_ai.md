## 개요

AI 호출의 전 과정을 담당한다. 프로젝트의 심장이다.

| 모듈 | 담당 |
|---|---|
| `resilience.py` | 재시도·타임아웃·오류 로그. **모든 층위 호출이 통과해야 하는 관문** |

## 설계 의도

### 층위를 나눈 이유 — 비용과 정확도의 분리

```
판단층위   유형 결정. 캐시를 읽지 않는다 → ASK·ROLL은 여기서 끝
지시층위   묘사 지시문 + 퀘스트 선택. 캐시를 읽는다
묘사층위   실제 출력. 스트리밍
추출층위   수치 판독. 캐시를 읽지 않는다 (비용 절감) [코드]
```

> *"추출은 출력물에서 값을 읽어내는 작업이므로 세계관 룰북 참조가 불필요하다. 따라서 세션 캐시를 읽지 않는다(비용 절감)."* `[코드]`

### 판단을 수치로 — 이분적 판단을 모델에 주지 않는다

> *"추출층위에는 '적용 기준'을 알려주지 않는다. 범위별 가이드만 제시하고, 임계값 비교와 실제 상태 적용은 이 모듈(코드)이 담당한다. 이분적 판단(부여할까 말까)을 모델에 위임하지 않고 기준을 확실히 하기 위함이다."* `[코드]`

모델은 `status_scores: [{target, status, score: 0~100}]`만 보고한다. 71 이상이면 부여, 30 이하면 해제라는 사실을 **모른다.**

같은 상황에 같은 결과가 나오고, 임계값을 시나리오별로 조정할 수 있다.

### 응답 지연 시 원 응답을 버린다

> *"자체 타이머를 두고, 타이머를 넘겨 원 응답이 도착해도 그것을 쓰지 않는다. 그러지 않으면 재시도 결과와 원 응답이 경합해 묘사가 중복 출력된다. asyncio.wait_for는 타임아웃 시 태스크를 취소하므로 이 요건을 충족한다."* `[코드]`

### 오류 종류를 사용자에게 알리지 않는다

> *"서버오류·검열·사용량 차단·응답 지연 등 턴 진행에 문제가 생기는 모든 경우, 대기 메시지에 '문제 발생'만 알리고(종류는 전달하지 않음) 재시도한다."* `[코드]` (기획 규정)

`USER_FACING_NOTICE`가 단일 문구다. 오류 상세는 `error_log.txt`로 분리된다.

### NPC를 델타로만 주입

> *"모든 default_npcs는 캐시 룰북 [3. NPC 사전]에 전체 수록되므로 프롬프트에 중복 주입하지 않는다. 프롬프트에는 설정 필드나 스탯이 캐시와 달라진 NPC만 델타(차분)로 주입한다."* `[코드]`

NPC의 `resources`·`statuses`는 **주입 대상에서 제외됐다.**
> *"매 턴 델타로 실려 토큰을 소모하는 데 비해 서사 기여가 낮아 폐지했다."* `[코드]`

### 나이는 코드가 계산한다

> *"birth_year가 있는 NPC의 나이를 코드가 계산해 넣는다. 모델에게 뺄셈을 시키지 않기 위함이다(4.16.0 설계)."* `[코드]`

## 데이터 구조

### 추출 응답 스키마 (`EXTRACTION_RESPONSE_SCHEMA`)

9개 필드 전부 `required`다.

| 필드 | 타입 | 내용 | 미확인 시 |
|---|---|---|---|
| `datetime` | obj | `{date, time_of_day}` | "미확인" |
| `location` | obj | `{name, faction_context}` | "미확인" |
| `item_changes` | arr | `[{target, item, delta}]` | 빈 배열 |
| `status_scores` | arr | `[{target, status, score}]` 0~100 | 빈 배열 |
| `quest_progress` | obj | `{advance, deviation}` 0~100 | — |
| `npcs_met` | arr | 이름 문자열 | 빈 배열 |
| `companions` | obj | `{joined[], left[]}` — **변화만** | 빈 배열 둘 |
| `secret_awareness` | int | 0~100 | 0 |
| `situation` | obj | `{tag, tension}` | — |

**수치 구간 가이드** (모델에게 주는 것)
```
status_scores    0-30 징후 없음 / 31-70 조짐 있음 / 71-100 명백함
quest_advance    0-30 정체 / 31-70 진전 / 71-100 결정적 진전
quest_deviation  0-30 궤도 내 / 31-70 방향 차이 / 71-100 이탈
secret_awareness 0-30 전혀 모름 / 31-70 의심·단서 / 71-100 명확히 인지
tension          0-30 평온 / 31-70 경계 / 71-100 위기
```

### 임계값 (`THRESHOLDS`)

| 키 | 기본 | 용도 |
|---|---|---|
| `status_apply` | 71 | 이상이면 상태 부여 |
| `status_clear` | 30 | 이하이면 기존 상태 해제 |
| `quest_advance` | 71 | 이상이면 케이스 진전 |
| `quest_deviated` | 71 | 이상이면 재계획 트리거 |
| `tension_high` | 71 | 이상이면 긴장 국면 (BGM 판단) |
| `secret_reveal` | 71 | 이상이면 이면정보 인지 |

시나리오 JSON의 `extraction_thresholds`로 항목별 오버라이드 가능. `[코드]`

**31~70 구간은 아무 일도 일어나지 않는다.** 부여도 해제도 안 되므로 상태가 유지된다. 의도된 이력 현상(hysteresis)으로 보인다. `[추정]`

### `prompt.py`

#### `PromptBuilder` — 묘사층위 프롬프트 조립

**조립 순서** (`build_prompt`)
```
① add_memory_block()          압축 기억
② add_note_block()            GM 실시간 노트
③ add_player_block()          PC 스탯·외형·자원·상태
④ add_npc_override_block()    NPC 델타
⑤ add_recent_action_block()   이번 턴 대화
⑥ add_gm_instruction_block()  지시층위 산출물
⑦ add_place_block()           장소 ⚠️ 작동 안 함
⑧ add_quest_block()           퀘스트 ⚠️ 작동 안 함
⑨ add_rule_enforcement_block() 강제 룰
```

> *"할루시네이션을 통제하기 위해 '요약 → 캐릭터 → NPC 델타 → 기억 → 행동 → 룰' 순서의 엄격한 정보 주입 포맷을 시스템 레벨에서 강제."* `[코드]`

**`manifest`** — 실제 주입된 온디맨드 정보를 기록한다. 비용 보고 임베드에 쓰인다.
`session.last_proceed_manifest`에 저장(비영속). `[코드]`

##### `add_player_block()`

상태이상이 없어도 **"없음"을 명시 출력**한다.
> *"해제 후에도 AI가 이전 상태를 언급하는 오류를 방지한다."* `[코드]`

##### `add_npc_override_block()`

가장 복잡한 블록(129줄). 캐시와의 차분만 뽑는다.

```
세션 생성 NPC (default에 없음)
  캐시에 있으면 → 스냅샷 대비 delta
  캐시에 없으면 → 전체 프로파일

디폴트 NPC
  info_fields가 있으면 → 값이 다른 필드만
  없으면 → details 문자열 전체 비교
스탯은 ability_stats 순서로 정렬, base에만 있던 것은 빈 값으로 표시
```

**나이 주입** — `birth_year`가 있으면 `timeline.compute_age`로 계산해 별도 줄에 넣는다.

##### `add_rule_enforcement_block()`

**개연성·예법·연속성 5개 룰**을 매 턴 넣는다.
> *"AI 집중도 한계 보정용 살라이언스 강화."* `[코드]`

```
① 턴 연속성 — 이미 서술된 것을 되풀이하거나 시간을 되감지 말 것
② 확립된 사실 잠금 — 정체·사건·아이템·위치를 번복하지 말 것
③ 개연성·예법 — 세계관·항렬·경어에 어긋나는 창작 금지
④ 인물 반응 스케일 — 명성·지위·나이에 비례
⑤ PC 대사·행동·감정 창작 금지 — @대사:PC이름| 마커도 금지
```

**대사 마커 규약**도 여기서 지시한다. 예시에 `강철수`가 등장한다(영도 NPC).

`status_code_block`이 있으면 상태창 출력 지시를 덧붙이며, **현재 턴 수 + 1**을 기입하게 한다.

##### `add_place_block()` / `add_quest_block()`

### `cogs/gm.py` — 층위 오케스트레이터

#### `_run_gm_logic_loop` (253줄)

**턴 진행의 본체.** 순서는 다음과 같다.

```
① 세션 오픈 확인 (is_session_open)      → 닫혀 있으면 차단
② 잔액 확인 (max_ink vs balance)         → 부족하면 차단
③ _simulate_narrative_directions()      개연성 시뮬레이션
④ _call_judgment()                      판단층위 → action 결정
⑤ action이 NARRATE·PROCEED면
     _call_gm_logic()                    지시층위
     _apply_quest_choice()               퀘스트 시작
⑥ action별 분기
     ASK      → 되묻기 출력. clarify_count 증가
     NARRATE  → _dispatch_narrate()
     ROLL     → _dispatch_rolls()
     PROCEED  → _finish_proceed_and_continue()
⑦ save_session_data()
```

**ASK·NARRATE 누적 한계** — `gm_clarify_count`·`gm_narrate_count`가 일정 이상이면 `_forced_proceed_instruction`으로 강제 진행한다. 무한 되묻기를 막는다. `[추정]`

#### `_run_extraction` (261줄)

```
① build_extraction_targets()            타겟 목록
② build_extraction_limits()             유효 목록 주입
③ AI 호출 (캐시 미사용)
④ parse_extraction()
⑤ to_world_timeline()                   위치·시간 갱신
⑥ release_resident_companions()         장소 이동 시
⑦ apply_companions()                    동행 갱신
⑧ apply_extraction()                    상태·소지품 적용
⑨ summarize_for_report() → 마스터 보고
```

#### `_call_judgment` (93줄) · `_call_gm_logic` (187줄)

각각 판단·지시층위를 호출한다. **두 함수 모두 7단계(호출·토큰·비용·누적·로그·턴로그·파싱)를 직접 수행한다.**

## 흐름

### 한 턴의 전체 경로

```
플레이어 발언
  ↓
on_message → _handle_player_message → _process_actions
  ↓
_run_gm_logic_loop
  ├ WaitingStatus.begin("judgment")
  ├ _simulate_narrative_directions()   [AI 호출 1]
  ├ _call_judgment()                   [AI 호출 2] 캐시 X
  │    → ASK/NARRATE/ROLL/PROCEED
  ├ (NARRATE·PROCEED) _call_gm_logic() [AI 호출 3] 캐시 O
  │    → proceed_instruction, quest_choice, info_access
  ├ _apply_quest_choice()
  └ 분기
      PROCEED → _finish_proceed_and_continue
                  → game._execute_proceed  [AI 호출 4] 캐시 O
                       PromptBuilder.build_prompt()
                       스트리밍 출력
                       (병렬) _run_extraction  [AI 호출 5] 캐시 X
```

**AI 호출 5회.** ASK·ROLL이면 2회에서 끝난다.
