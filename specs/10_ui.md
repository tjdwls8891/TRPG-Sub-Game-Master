- **모듈**: `core/display.py`(623) · `ui.py`(293) · `chat_guard.py`(82)
- **연관 cogs**: 전역 (`main.py`의 `on_message`)
- **기준 버전**: v5.30.0
- **작성 상태**: 완료 (미검증 — 사용자 확인 대기)

## 개요

플레이어가 보고 누르는 것을 다룬다.

| 모듈 | 담당 |
|---|---|
| `display.py` | 디스플레이 채널 — 상태 표기와 조작 UI를 단일 메시지로 |
| `ui.py` | 주사위 뷰, 채널 삭제 뷰 |
| `chat_guard.py` | 채널별 채팅 권한 검증 (봇 레벨 단일 훅) |

`chat_guard.py`는 82줄이지만 **모든 메시지가 통과하는 관문**이다.

## 설계 의도

### 디스플레이는 메시지 하나

> *"채널에 메시지 하나를 두고 edit()으로 갱신한다. 매번 새로 보내면 채널이 지저분해지고 이전 UI 버튼이 살아남아 중복 조작이 가능해진다."* `[코드]`

### 갱신 계층을 코드로 나누지 않는다

> *"기획서는 갱신 시점을 5계층으로 구분하지만, 임베드 조립은 API 호출이 아니라 문자열 작업이라 부분 갱신의 이득이 없다. `refresh()`는 항상 전체를 다시 그리고, 계층 구분은 '언제 호출하는가'로만 표현한다."* `[코드]`

**기획을 그대로 구현하지 않고 근거를 들어 단순화한 사례다.**

### 권한 검증을 단일 훅으로

> *"권한 검증이 cog마다 흩어져 있으면 새 채널 유형이 추가될 때 누락이 생긴다. 기획 규정도 '채팅 이벤트 발생 시 최우선 단계로 채널과 아이디를 받아 필요한 모든 경우에 권한검증 실시'이므로 진입점을 하나로 둔다."* `[코드]`

### 이중 차단

> *"1차는 서버 권한(채널 오버라이드)으로 막고, 2차로 새어 들어온 메시지를 삭제한다. 권한으로 막는 것이 원칙이고 삭제는 보완이다."* `[코드]`

### 알림은 스스로 사라진다

디스플레이는 상태판이다. 확인·결과가 쌓이면 상태 임베드가 위로 밀려난다.
`close_notice`가 확인 메시지를 결과로 바꿔 쓰고 잠시 뒤 지운다. `[코드]` (5.24.3)

### 메모리 누수 방지

> *"채널 삭제 시 파이썬 가비지 컬렉터가 객체를 온전히 수거할 수 있도록 반드시 메모리 참조를 끊어주는 메모리 누수(Memory Leak) 방지 로직."* `[코드]`

`active_sessions`가 채널 3개로 같은 세션을 가리키므로 **전부 해제**해야 한다.

## 데이터 구조

### 디스플레이 임베드 구성

```
제목    🎲 {시나리오}
설명    세션 {종류} · {공개} · {상태}
색      🟢 오픈 0x2ECC71 / 🔴 만료 0xE74C3C / ⚫ 클로즈 0x95A5A6

필드
  진행 상태      턴 · 작중 시각 · 위치
  비용          총 잉크 · 직전 턴 · 다음 턴 예상 (+TTS 구분)
  세션 오픈      캐시 토큰 · 만료 예정 · 선결제
  또는 세션 만료  안내
  캐릭터        PC 프로필
  퀘스트        진행 중
  미디어        플래그 상태
  기억          압축 방식·횟수
```

### 버튼 (`custom_id`)

| id | row | 기능 |
|---|---|---|
| `disp:tts` `disp:image` `disp:bgm` `disp:sfx` | 0 | 미디어 토글 |
| `disp:vol_down` `disp:vol_up` | 1 | 볼륨 |
| `disp:rewind` `disp:rewind_multi` `disp:restart` | 2 | 되감기·재시작 |
| `disp:open` `disp:close` `disp:pay` | 3 | 세션·결제 |

**상태별 잠금** `[코드]`
```
턴 진행 중        rewind · restart · tts · image · open · close 잠금
세션 열림         open 잠금
세션 닫힘·만료     close 잠금
```

### 상수

| 상수 | 값 | 용도 |
|---|---|---|
| `NOTICE_SECONDS` | 3 | 차단 안내 표시 시간 (기획 규정) |
| `notify` 기본 | 12초 | 알림 자동 소멸 |
| `close_notice` 기본 | 12초 | 확인→결과 후 소멸 |

## 기능 목록

### `chat_guard.py`

#### `_reject(message, reason) -> bool`

메시지를 삭제하고 3초짜리 안내를 띄운다. 항상 `False`.
**호출부** — 내부 6곳

#### `chat_guard(bot, message) -> bool`

**모든 메시지가 통과하는 관문.**

**판정 순서**
```
① 봇 메시지        → False
② DM               → True (별도 인터페이스 소관)
③ 세션 채널 아님
     GM 스페이스    → 거부 ("버튼을 이용해 주십시오")
     그 외          → True
④ 디스플레이 채널
     awaiting_display_input이면 → True (플래그를 끄고 1회만)
     아니면                     → 거부
⑤ 마스터 채널
     오너 또는 참가자 → True
     아니면           → 거부
⑥ 게임 채널
     참가자 아님       → 거부
     is_processing     → 거부 ("턴 진행 중")
     extraction_pending → 거부 ("정리 미완료")
     통과
```

**호출부** — `main.py:85` **한 곳**

**주의점** — `awaiting_display_input`을 **여기서 끈다.** 유지 시간 입력이 1회만 허용되는 근거다.

### `ui.py`

#### `_cleanup_session_memory(bot, channel_id)`

**무엇을 하는가** — 채널 삭제 시 세션 참조를 끊고 마감 처리를 한다.

## 흐름

### 메시지 처리

```
디스코드 메시지
  ↓
main.py:85  chat_guard(bot, message)
  ├ False → 여기서 끝 (삭제 + 3초 안내)
  └ True
     ↓
   bot.process_commands  또는  cogs의 on_message
```

### 디스플레이 갱신 시점

```
세션 시작        session.py
턴 종료          gm.py (reason="turn_end")
되감기 후        gm.py (reason="rewind")
세션 열기/닫기    display.py (reason="reopen"/"close")
캐시 만료 감지    presence.py (reason="expired")
인트로 후        session.py (reason="intro")
```

### 세션 마감

```
!채널정리 → ChannelDeleteView
  ↓ 삭제 확인
_cleanup_session_memory
  active_sessions 3개 키 해제
  stats.bump(session_seconds, ink_spent)
  refresh_boards 예약
  settle_on_session_close → 압축 선결제 환급
  ↓
채널 삭제
```

## 발견 사항

> ⚠️ **`_flag_style` 호출부 없음**
> 플래그 버튼 색 헬퍼. `DisplayView`가 직접 판정하는 듯하다.

> ⚠️ **세션 마감 처리가 채널 삭제에 묶여 있다**
> `_cleanup_session_memory`가 통계·환급·보드 갱신을 모두 한다.
> `!채널정리`로 채널을 지워야 이것이 일어난다.
> **세션만 닫고 채널을 남기면 압축 선결제가 환급되지 않고 통계도 누락된다.**

> ⚠️ **`refresh`가 별칭으로만 쓰인다**
> `refresh as refresh_display`. 단순 검색으로는 미사용으로 오판하기 쉽다.
> `ink.refund_ink`(`as _refund`)와 같은 패턴이다.

> 🔁 **`build_embed`가 163줄**
> 9개 필드를 한 함수가 조립한다.

> ⚠️ **`display.py`가 `format_ink`를 임포트하나 쓰지 않는다**
> (cost 영역에서도 지적)

> ⚠️ **`chat_guard`의 게임 채널 판정이 `is_processing`에 의존**
> 이 플래그가 예외로 남으면 채널이 영구 잠긴다. 해제 경로 확인이 필요하다. `[확인 필요]`
