## 1. 후속 묘사 제거

**지시** — 후속 묘사를 제거한다. 단 도입 원인과 단순 삭제 시의 손실을 찾아 보완한다.

**현재 구조(문서 기준)** — DYNAMIC 자동 턴: 묘사 → 추출(`world_observation`) → 보충 진행 → *필요 시 후속 묘사 1회(같은 턴 비용)* → READY → 커밋 → 후속 묘사 송출.
관련: `core/turn_world.py`(`ForegroundContinuationPlan`·`process_observation`), `cogs/gm.py`, `core/turn_preparation.py`, `core/message_lifecycle.py`(출력 소유).

**착수 시 조사**
- 도입 근거: H05 완료 번들(`handoff/H05_COMPLETION_BUNDLE.md`)·DEVLOG에서 "묘사 이후 세계 진행이 장면에 닿는 경우"를 어떻게 다뤘는지.
- 삭제 시 손실 후보: 보충 진행 결과(같은 분 사건·NPC 도착 등)가 플레이어에게 보이지 않는 문제, 다음 턴 묘사로 이월할 때의 시간·관찰 정합.
- 보완 방향 후보(결정 필요): ① 보충 진행 결과를 다음 턴 지시층위에 "직전 이후 일어난 일"로 주입 ② 묘사 전에 진행을 확정해 한 번의 묘사에 포함 — 2번 항목과 직결.

**연동** — 2번과 함께 설계한다(갱신 시점이 바뀌면 후속 묘사의 존재 이유가 달라짐). TTS(자동 턴 더빙 대상에서 후속 묘사 제외 규칙), 비용(같은 턴 비용 멤버), 메시지 5분류, 되감기·재생성 이력.

## 2. 세계 상태 갱신 시점 → 턴 종료 시점

**지시** — 세계 상태 업데이트를 턴 종료 시점으로 앞당긴다. 현 시점을 택한 이유를 찾고 변경 단점을 보완한다. 이 시점에 맞춰진 개발을 전수조사한다.

**착수 시 조사**
- "현재 갱신 시점"을 코드로 확정: READY → `CommitCoordinator` 커밋, 구간 TRANSIT의 다음 턴 이월, 같은 분 진행·wakeup이 실제로 언제 정본에 반영되는지.
- 현 시점 결정 근거: H02~H06 번들(커밋 단일 권위, base quiescence, 묘사 관찰이 같은 분 선후를 정함 `SameMinuteNarrativeTie`).
- 전수조사 대상(이 시점을 전제로 한 개발): 후속 묘사(1번), 관찰 매니페스트·`process_observation`, TRANSIT 이월, 디스플레이 상태판 갱신 시점, 되감기 레코드(`turn.delta`), 재서술(같은 revision에서 세계 계획 재수립), 캐시 재발급의 기준 world_version.
- 단점 후보: 묘사 실패 시 이미 커밋된 세계와 묘사 불일치, 청구 0 실패 경로와의 정합, 재생성 시 세계 재계획.

**결정 필요** — "턴 종료 시점"의 정확한 정의(커밋 직후 다음 턴 시작 전 진행 확정인지, 묘사 전 진행 확정인지).

**지시** — 시나리오별 비용 데이터를 자동 수집하고 통계로 비용 안내 정확도를 높인다. 캐시량별·입력량별 판단을 세분화한다. 비용 예측 보고를 일관화하고 전수조사한다. 실비용·예측 비용·보고/기록 비용·TTS 비용·사고 토큰을 정확히 추적해 일치시킨다.

**착수 시 조사**

- 원장 합계 ↔ Settlement 청구 ↔ 보고 임베드 ↔ 구조 로그 대사(對査) 차이.
- `total_cost`/`total_usd` 호환 미러는 규칙 입력 금지(기존 원칙 유지).

**결정 필요** — 통계 반영 방식(고정 단가 + 실측 토큰 분포, 최소 표본 수, 시나리오별/층위별 구간), 실청구(Cloud Billing) 대조는 미완 항목과 별개로 둘지.
